# Contributing to TrilhaAtlas

A good contribution starts with a study problem someone can reproduce. A lesson might assume an unfamiliar concept, a video might start after the relevant explanation, or a completed skill might disappear after an update. Include the skill names, the expected behavior and a small example. [TrilhaAtlas issues](https://github.com/Chummy26/TrilhaAtlas/issues)

## Curricula and materials

You can build a curriculum for any subject. Give each skill an observable objective, identify what a beginner needs to know first, and connect the skill to a unit. Attach optional books by chapter and videos by timestamp. Use sources you can share, and record their authorship and terms. [Author a study domain](docs/authoring-domains.md)

Share curriculum definitions or synthetic examples. Keep personal conversations, learner events, downloaded books, credentials and provider logs in local storage. Use invented answers and a temporary data directory for bug reports and screenshots.

## Code and pull requests

Keep changes focused. Run `npm run typecheck`, `npm run lint` and the tests for the affected feature. In the pull request, explain what a learner can do differently, how you verified it, and any limitations. Include a screenshot for a visible interface change.
