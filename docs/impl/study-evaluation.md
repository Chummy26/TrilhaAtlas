# Evaluating a study path

Use two separate records. A software run shows what the app and tutor did. Independent learner assessments show what someone learned. Keep prompts, model and connection IDs, curriculum certificate, rubric, dates, and aggregate scores with each run. Keep transcripts, PDFs, OAuth credentials and identifiable learner records in the local evaluation profile.

## End-to-end acceptance

Start with a fresh local workspace. Use a small, verifiable task such as reading elevation and comparing slopes on a topographic map. Record the initial domain, time to the first lesson and provider usage. Submit the goal through the creation route, poll until the tree is ready, then retry the same request ID. Check that there is one installed tree, one seed ledger and no duplicate model calls. Select the domain and open its map and first lesson.

For each region, inspect the first skill, the exit task and every cross-region prerequisite. Use a cold learner walkthrough to find vocabulary, procedures or tools used before introduction. Report broken dependencies over the number reviewed, including the actual edge and missing skill. Record separate denominators for book searches, video searches, relevant hits and working locators. A catalog hit counts as usable only after checking that its section or segment actually teaches the stated objective.

Attach a short reference with a known fact, physical page and a plausible distractor. Ask for an explanation, correct a misconception, start another lesson and ask a transfer question. Check the cited passage against the original. Switch to an unrelated domain and check for leaked details. Submit two distinct wrong answers about the same prerequisite, then an independent correct answer. Log whether remediation targets the missing step and whether the original goal and existing mastery remain intact. Record provider errors, missing materials, retries and aborted runs alongside successes.

Score factual accuracy, citation support, fit to demonstrated knowledge and usefulness of the next step separately (0 incorrect or missing, 1 partial, 2 complete). Blind two human raters to model and condition, randomize answer order, retain initial scores and resolve disagreements against the reference. Repeat identical scenarios on each model with independent generations. A single run is a feasibility check.

## Learning over time

Before the first lesson, select two comparable skill sets and write parallel assessment forms with an answer key. Shuffle which skill set receives memory-assisted tutoring and which receives the same model with a fixed nonpersonalized lesson. Keep study time, reference access and item difficulty comparable. Record prior familiarity. With one learner, use different skills in each condition to limit carryover and report individual trajectories.

Assess without hints at baseline, immediately after practice, and 7 and 28 days later. Reserve unseen transfer items for follow-up. Record first-attempt correctness, rubric points, time, hints during practice and missed assessments. Report paired changes by skill, delayed retention and transfer separately, alongside sample sizes and uncertainty where the design supports it. XP, time in the app and unlocked nodes describe activity. An improvement in independent delayed performance supplies evidence of learning. Simulated learners can exercise transitions, but cannot supply that outcome.
